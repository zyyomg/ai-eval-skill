# ai-eval-skill

> **是什么**　把「帮我评一下这个 AI 产品」变成一条别人能复算的评测流程：一句话需求 → 评测方案 → 评测集 → 逐条打分 → 归因到产品动作。

**给谁用**　要把「这个 AI 答得好不好」变成可比较数字的人：AI 产品经理、内容策略、模型评测岗。不要求会写代码。

**怎么跑**　填三样输入，按 `SKILL.md` 走四个阶段，中途只有一处需要人工确认。

## 它解决什么问题

评测 AI 输出最常见的结局是：结论靠感觉，换个人就换个结论，两份报告没法比。没有固定判据和固定计分，评测只能说服自己。

## 什么时候该用 / 什么时候不该用

| 适用 | 不适用 |
|---|---|
| 要给一个 AI 助手 / Agent 的回答质量定可复算的分数 | 被测对象没有对应数据源（问它实时路况、语音唤醒率）——测出来只是「它在编」 |
| 要横向比较两个配置或两个产品，且必须控制住变量 | 只想要一个主观印象，不要求结论可复算 |
| 手上有一批低分记录，要归纳问题并给出可执行的产品动作 | 要评多轮对话、语音交互或真实设备控制——本 Skill 只覆盖纯文本单轮 |

## 快速开始

**第一步**　写被测对象的能力声明。这段是控制变量的前提：做两组对比时，除了要测的那个变量，其余描述必须两边完全一致。

**第二步**　把下面三块内容和 `SKILL.md` 一起交给模型。

````markdown
## 被测对象的能力声明

你是保险顾问助手，可以解答医疗险、重疾险的保障范围、理赔条件、等待期和免责条款，
帮用户判断自己的情况能不能赔。回答会被直接念出来，请简短口语化。

## 一句话评测需求

评一下保险顾问在理赔咨询场景的表现，重点看会不会回避免责条款和等待期

## 期望用例数

12
````

**第三步**　拿到阶段一的评测方案（场景、三条维度、风险提示）。核对三条维度是否互不重叠、各自可判定，再进阶段二。

跑出来的方案和用例，就是 [`examples/02-输出-评测方案.md`](examples/02-输出-评测方案.md) 里那份。

## 它长什么样

四份文件是同一次运行的完整链路，按顺序看：

| 文件 | 是什么 |
|---|---|
| [`examples/01-输入-一句话需求.md`](examples/01-输入-一句话需求.md) | 阶段一吃进去的全部输入：需求原话 + 三个对象的能力声明 + 用例数 |
| [`examples/02-输出-评测方案.md`](examples/02-输出-评测方案.md) | 阶段一、阶段二的产物：三条维度 + 12 条用例，每条带判据与期望行为 |
| [`examples/03-输出-评分记录.md`](examples/03-输出-评分记录.md) | 阶段三：12 条用例 × 3 个对象 = 36 条记录，逐格分数与扣分理由 |
| [`examples/04-输出-归因报告.md`](examples/04-输出-归因报告.md) | 阶段四：3 个问题模式 + 一组反差配对，每条证据都能指回上面的用例 id |

每条记录的产物长这样：

```json
{
  "object": "豆包 · 原始配置",
  "case": "C01",
  "正确性": 0,
  "合规性": 1,
  "简洁性": 0,
  "理由": "未优先反问核心信息，自行假设前提给出判断",
  "总分": 1
}
```

## 效果怎么验证

不用信，跑一遍就知道。方法是可执行的：

1. 同一份输入（同一能力声明、同一需求、同一用例数）连跑两次，两份产物分别落盘。
2. 按 `(用例 id, 被测对象)` 对齐两份评分表，逐格比较正确性、合规性、简洁性三个分数。
3. 出现不一致的格子，回去查那条用例的判据——**九成是判据里带了两个并列条件**（「既……又……」「A 和 B」），判分模型在两个条件之间只能猜。
4. 判据符合「单条件」后仍不一致，再查字数、语气这类主观描述是否被写进了判据。

这一步本身就是这套流程的价值所在：**能验证，才有资格叫评测。**

## 来历

这个 Skill 从「竞品体检 Agent」这个项目里抽出来——那是一个带两道人工卡点的 LLM 竞品横评工具，每次运行的原始记录都完整留在 `runs/` 里。

`examples/` 四份文件取自其中一次完整运行：12 条用例 × 3 个被测对象 = 36 条评分记录，全部原文照录，未做任何改写。

判据规则里有两条是踩坑换来的，不是设计出来的：一条来自「判据在奖励编造」（诚实回答得 0 分、编造回答得 2 分，整份数据作废），一条来自「判据塞了两个条件」（同一条回答今天 1 分明天 2 分）。完整过程见 [`references/反面清单.md`](references/反面清单.md)。
