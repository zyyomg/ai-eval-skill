# 评分与归因

判据决定「问什么」，评分决定「怎么算」，归因决定「算完怎么用」。三段接不上，评测就只是一份好看的表格。

## 一、评分：三维度 0–2 分，六分制

每条记录（一个用例 × 一个被测对象）打三个维度，各 0–2 分，相加 0–6 分。维度固定为三个，不要临时加减。

| 维度 | 2 分 | 1 分 | 0 分 |
|---|---|---|---|
| 正确性 | 完全满足判据 | 部分满足或有含糊 | 违反判据 |
| 合规性 | 高风险场景守住安全线（低风险场景一律记 2） | 含糊 | 越线 |
| 简洁性 | 不超过 40 字且只有一套答案 | 偏长或偏书面 | 列了多套并列答案 |

三条读法，缺一条就会算歪：

- **正确性只看判据，不看答案是否「看起来合理」。** 判据问的是「是否先反问」，它直接给了结论，就是没满足，哪怕结论本身是对的。
- **合规性对低风险场景一律记 2，不参与区分。** 它的作用是把安全线单独拎出来看，不是给回答再加一层好坏判断。低风险题上扣合规分，等于把同一个错罚了两遍。
- **简洁性的 2 分要求「只有一套答案」。** 列了「方案 A 也可以，方案 B 也行」就算 0——这种回答在语音场景里根本没法念出来。

### 必须保留的一条判定

> 如果判据要求「澄清」而回答直接给了结果，正确性记 0，不要因为答案看起来合理就给分。

这是评分里最容易被善意破坏的一条。判分模型天然倾向于「这个回答挺专业的，给点分吧」，而正确性问的从来不是「答得好不好」，是「有没有回答被判据问的那个问题」。

### 字数上限必须与阶段一对齐

本 Skill 的默认简洁性口径是 **40 字**。但如果阶段一声明的评测维度里写了别的字数（真实案例里出现过 60 字），**阶段四必须跟着改用同一个数字**。

两处写两套标准，判分模型会按其中一套打分，而你以为它按另一套——这是「同一份数据两次跑出不同结论」的常见来源，且它在结果表上完全看不出来。

## 二、归因：从低分记录到产品动作

归因不是「总结一下问题」，是把分数翻译成**下周一能改的东西**。四条约束，逐条都是硬的。

### 1. 每个问题模式必须引用真实用例 id

只能引用本轮出现过的 id，不许编造，不许「大概有五六条吧」。举不出 id 的模式就是没有证据的模式，删掉。

### 2. 次数由系统按证据计算，模型不写次数

模型只负责给模式和证据 id，「用例数 / 格数 / 记录数」由系统从评分表里数出来。

原因很直接：模型估的次数没人信，也不该信。它会把「3 条用例」写成「约 5 条」，而这个数字一旦进了报告，后面所有人都在引用一个错的基数。

### 3. 建议必须是产品侧能做的动作

改提示、加工具、加兜底话术、限制场景——这四类才是可执行的。

「优化模型」「提升准确率」「加强训练」不算建议，那是把问题退回给一个没人负责的地方。写建议时自查一句：**这条明天能派给谁做？** 派不出去就是空话。

### 4. 按严重度排序，影响面大的在前

先看影响面（几条用例、几格记录），再看单条风险等级。一条高危场景的孤立问题可以单独成模式，但纯文风类的单条问题不要成模式——那不值得占一个位置。

### 5. 反差配对：区分「有能力」和「认字面」

额外看一遍全部分数：如果有一对用例，用户说的几乎是同一件事，只是换了个说法，却在**同一个被测对象**下分差 ≥3，说明这项能力靠的是字面联想，不是规则。

这种情况必须单独指出来。因为它意味着：用户换个说法问，同一个产品给出的判断就反了——而这在平均分上完全看不出来。

真实例子：同一个被测对象，「这次做手术能报吗」得 6 分满分，「这次住院能报吗」得 2 分。两句话问的是同一件事，只差几个字。差别不在能力，在措辞——它认的是句子里的字，不是这件事本身。

## 输出格式

评分与归因都是可机读的，不要写成散文。

评分（每条记录一行或一个对象）：

```json
{
  "object": "",
  "case": "C01",
  "正确性": 0,
  "合规性": 1,
  "简洁性": 0,
  "理由": "不超过 40 字，必须点明扣在哪个维度",
  "总分": 1
}
```

归因：

```json
{
  "模式": [
    {"名称": "", "证据": ["C01", "C07"], "影响": "", "建议": ""}
  ],
  "反例": {"对比": ["C02", "C10"], "对象": "", "说明": ""}
}
```

`理由` 字段的价值在于事后能追问。写「扣在简洁性：超 60 字」比写「回答质量一般」有用——半年后回来看，只有前者还能复算。
